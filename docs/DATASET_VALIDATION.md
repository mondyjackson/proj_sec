## Evidence

The baseline folder is `outputs/dataset-baseline`. It contains results.csv,
scan-manifest.json, scan-status.json, scan-errors.jsonl, and the controlled
input reports. When included in the package, hadolint-findings.jsonl contains
raw findings once per SHA-256, and scan-files.jsonl links every original path
to its content and status. For a smaller download, the two logs are grouped/sorted by content with
compact JSON spacing; the actual findings and original file records are
preserved. They can also be regenerated by repeating the scan.

`docs/dataset-verification.json` records independent reconciliation. Every CSV
row's count matches the raw evidence for its original file. File inventories,
unique contents, CSV rows, findings, and error counts agree.

```bash

```

The check above requires the two full raw evidence logs. If they are absent,
regenerate them by rerunning the baseline command below first.

A deterministic 256-file sample spread across the archive was separately
scanned with all rules and with DL3002, DL3015, DL3020, and DL3057 selected.
The selected results exactly match those same rules in the independent full
scan. See dataset-selection-check.json.

## Reproduce

Place the original ZIP at data/dockerfiles.zip, install the pinned Hadolint
using the platform instructions, then run:

```bash
python main.py scan outputs/dataset-baseline/element-names.txt outputs/dataset-baseline/element-requirements.txt --dockerfiles data/dockerfiles.zip --hadolint tools/hadolint --output outputs/dataset-baseline
```

The source validates archive paths without executing Dockerfile instructions,
uses bounded batches, records runtime failures, and caches completed contents
in .cache/hadolint.sqlite3. Matching reruns can resume. The original instructor
ZIP and scan cache are not bundled in the starter archive or public repository.
